알고리즘을 이해하려면 무엇을 계산하는지뿐 아니라 왜 맞는지, 입력이 커질 때 얼마나 많은 일을 하는지도 봐야 한다. 검색과 정렬을 직접 따라가고, 반복 횟수를 함수로 표현하면 빅오 표기법이 무엇을 설명하는지 분명해진다. 특히 알고리즘 하나가 느리다는 사실과 문제 자체가 어렵다는 주장은 구별해야 한다.

## 1. 알고리즘의 조건과 최댓값 찾기

알고리즘은 문제를 해결하기 위한 명확한 명령들의 유한한 기술이다. 입력과 출력이 정해져 있어야 하고, 각 단계가 정확히 정의되어야 한다. 올바른 입력에서 정답을 내는 **정확성**, 유한한 단계 안에 끝나는 **유한성**, 각 단계를 실제로 수행할 수 있는 **효과성**, 특정 사례에만 한정되지 않는 **일반성**도 필요하다. 효과성은 “아주 빠르다”는 뜻이 아니라 기본 단계를 유한한 시간에 실행할 수 있다는 뜻이다.

길이가 $n\ge1$인 정수열의 최댓값은 다음과 같이 찾는다. 의사코드의 배열 인덱스는 1부터 시작한다.

```text
maximum(a[1..n]):
    best := a[1]
    for i := 2 to n:
        if best < a[i]:
            best := a[i]
    return best
```

$8,4,11,3,10$에서는 `best`가 $8,8,11,11,11$로 변한다. $5,1,8,3$에서는 $5,5,8,8$이다. $i$번째 원소까지 처리한 뒤 `best`가 앞의 $i$개 원소의 최댓값이라는 성질이 유지된다. 처음에는 원소 하나에서 참이고, 다음 원소와 비교해 더 큰 값을 남기므로 끝까지 유지된다. 종료 시 전체의 최댓값이 나온다.

원소끼리의 비교만 세면 $n-1$회다. 반복 조건 검사까지 비교로 세면 $n+(n-1)=2n-1$회다. 정확한 횟수는 계산 기준에 따라 달라져도 선형으로 증가한다는 사실은 같다.

## 2. 순차 검색과 이진 검색

### 순차 검색

```text
linear_search(x, a[1..n]):
    i := 1
    while i <= n and x != a[i]:
        i := i + 1
    if i <= n:
        return i
    return 0
```

`and`는 앞 조건이 거짓이면 뒤를 평가하지 않는 단락 평가로 읽는다. 따라서 범위 밖의 원소를 접근하지 않는다. 정렬되지 않은 배열에서도 사용할 수 있다.

$x$가 $i$번째 위치에 있을 때 원소와의 비교는 $i$회다. 반복 조건의 두 비교와 마지막 `if`까지 세면 $2i+1$회다. 없을 때는 전체 $n$개를 확인하고 종료하며 $2n+2$회다. 따라서 최악 시간은 $\Theta(n)$이다.

찾는 값이 반드시 존재하고 각 위치에 있을 확률이 같다면 평균 비교 횟수는

$$
\frac1n\sum_{i=1}^{n}(2i+1)
=\frac{n(n+1)+n}{n}=n+2.
$$

원소와의 비교만 세면 $(n+1)/2$회다. 어느 기준이든 평균은 $\Theta(n)$이며, 평균을 말할 때는 이러한 확률 가정이 필요하다.

### 이진 검색

이진 검색은 입력이 오름차순으로 정렬되어 있다는 조건을 사용한다.

```text
binary_search(x, a[1..n]):
    if n = 0:
        return 0
    i := 1
    j := n
    while i < j:
        m := floor((i + j) / 2)
        if x > a[m]:
            i := m + 1
        else:
            j := m
    if x = a[i]:
        return i
    return 0
```

$x>a[m]$이면 정렬 순서에 의해 $m$ 이하의 위치에는 답이 없다. 그렇지 않으면 $m$보다 뒤에는 더 큰 값만 있으므로 오른쪽 끝을 $m$으로 줄인다. 답이 있다면 항상 현재 구간 안에 남는다는 성질을 유지하면서 구간을 절반 정도로 줄인다.

배열 $1,2,3,5,6,7,8,10,12,13,15,16,18,19,20,22$에서 19를 찾으면 다음과 같다.

| $i$ | $j$ | $m$ | $a[m]$ | 다음 구간 |
|---|---|---|---|---|
| 1 | 16 | 8 | 10 | $[9,16]$ |
| 9 | 16 | 12 | 16 | $[13,16]$ |
| 13 | 16 | 14 | 19 | $[13,14]$ |
| 13 | 14 | 13 | 18 | $[14,14]$ |

마지막 원소가 19이므로 위치 14를 반환한다. 반면 $1,3,5,7,9,11,13,15$에서 4를 찾으면 구간이 $[1,8]\to[1,4]\to[3,4]\to[3,3]$으로 줄고 마지막 값 5가 4와 달라 0을 반환한다.

$n=2^k$이면 반복이 $k$번이고, 각 반복의 조건과 원소 비교를 두 번으로 세면 종료 검사와 마지막 동등 비교를 포함해 $2k+2$회다. 일반적인 $n\ge1$에서는 최대 $2\lceil\log_2n\rceil+2$회로, 최악 복잡도는 $\Theta(\log n)$이다. $n=10^6$이면 이 기준에서 최대 42회다. 다만 정렬되지 않은 데이터라면 정렬에 드는 비용도 별도로 고려해야 한다.

## 3. 버블 정렬과 삽입 정렬

### 버블 정렬

인접한 두 원소가 잘못된 순서이면 바꾼다. 한 번 훑으면 아직 정렬되지 않은 부분의 최댓값이 뒤로 이동한다.

```text
bubble_sort(a[1..n]):
    for i := 1 to n - 1:
        for j := 1 to n - i:
            if a[j] > a[j + 1]:
                swap(a[j], a[j + 1])
```

$5,2,4,6,1$을 정렬하면

| 단계 | 배열 |
|---|---|
| 시작 | $5,2,4,6,1$ |
| 1회전 | $2,4,5,1,6$ |
| 2회전 | $2,4,1,5,6$ |
| 3회전 | $2,1,4,5,6$ |
| 4회전 | $1,2,4,5,6$ |

원소 비교 수는

$$
(n-1)+(n-2)+\cdots+1=\frac{n(n-1)}2.
$$

위 구현은 교환이 없는 회전에서도 끝까지 실행하므로 이미 정렬된 입력에도 같은 횟수로 비교한다. $n=10$이면 45회이고 복잡도는 $\Theta(n^2)$다. 교환이 없으면 종료하는 최적화를 넣은 버전은 최선 경우가 달라진다.

### 삽입 정렬

앞부분이 정렬되어 있다고 유지하면서 다음 원소를 그 안의 올바른 자리에 넣는다. 여기서는 삽입 위치를 앞에서부터 찾는 버전을 사용한다.

```text
insertion_sort(a[1..n]):
    for j := 2 to n:
        i := 1
        while a[j] > a[i]:
            i := i + 1
        value := a[j]
        for k := j down to i + 1:
            a[k] := a[k - 1]
        a[i] := value
```

$i=j$가 되면 자기 자신과 비교하여 조건이 거짓이므로 탐색이 끝난다. 삽입할 값을 따로 저장한 뒤 원소들을 오른쪽으로 옮겨야 값이 덮어써지지 않는다.

| 단계 | 배열 |
|---|---|
| 시작 | $5,2,4,6,1$ |
| $j=2$ | $2,5,4,6,1$ |
| $j=3$ | $2,4,5,6,1$ |
| $j=4$ | $2,4,5,6,1$ |
| $j=5$ | $1,2,4,5,6$ |

이 버전에서 $j$번째 원소의 삽입 위치를 찾는 비교는 최대 $j$회이므로 총 $2+3+\cdots+n=n(n+1)/2-1$회다. $n=10$이면 최대 54회다. 이미 정렬된 입력은 앞에서 끝까지 탐색하므로 비교가 많고, 역순 입력은 삽입 위치는 빨리 찾지만 이동이 많다. 어느 쪽이든 전체 작업량은 이 구현에서 이차적으로 커질 수 있다.

흔히 사용하는 뒤에서부터 탐색하는 삽입 정렬은 이미 정렬된 입력에서 $\Theta(n)$이다. “삽입 정렬”이라는 이름만 보고 정확한 비교 횟수나 최선 경우를 정하지 말고 구현과 세는 연산을 확인해야 한다. 두 방식 모두 최악 시간은 $\Theta(n^2)$다.

## 4. 문자열 매칭

길이 $n$인 텍스트 $T$에서 길이 $m$인 패턴 $P$를 찾는다. 이동량 $s$는 패턴을 오른쪽으로 몇 글자 옮겼는지 나타내며 시작 위치는 $s+1$이다.

```text
string_match(T[1..n], P[1..m]):
    for s := 0 to n - m:
        j := 1
        while j <= m and T[s + j] = P[j]:
            j := j + 1
        if j > m:
            output s
```

$1\le m\le n$을 가정한다. 검사할 이동은 $n-m+1$개이며, 각 이동에서 최대 $m$글자를 비교하므로 최악 문자 비교 횟수는 $(n-m+1)m$이다.

| 텍스트 | 패턴 | 유효한 이동 $s$ | 시작 위치 |
|---|---|---|---|
| `eceyeye` | `eye` | 2, 4 | 3, 5 |
| `11001011` | `101` | 4 | 5 |
| `CATCACAGAGA` | `CAG` | 5 | 6 |

마지막 예는 텍스트 길이 11, 패턴 길이 3이라 총 9개 이동을 검사한다. 패턴이 겹쳐 나타날 수 있으므로 성공한 뒤에도 모든 이동을 계속 확인한다.

## 5. 탐욕 알고리즘과 최적성

탐욕 알고리즘은 각 단계에서 당장 유리한 선택을 한다. 선택이 간단하다는 사실만으로 최적해를 보장하지는 않는다.

### 거스름돈

큰 액면부터 남은 금액을 넘지 않는 동전을 선택한다.

```text
change(coins in descending order, amount):
    for coin in coins:
        count[coin] := 0
        while amount >= coin:
            count[coin] := count[coin] + 1
            amount := amount - coin
    return count, amount
```

마지막 나머지가 0이어야 정확하게 거슬러 준 것이다. 액면 1이 있으면 모든 음이 아닌 정수 금액을 만들 수 있다. 액면이 $25,10,5,1$이면 67은 $25+25+10+5+1+1$로 6개, 41은 $25+10+5+1$로 4개다.

이 액면 조합의 최적성은 교환 논증으로 보일 수 있다. 최소 동전 해에는 1짜리가 다섯 개 이상 있을 수 없다. 5짜리 하나로 바꾸면 동전 수가 줄기 때문이다. 같은 이유로 5짜리는 최대 하나, 10짜리는 최대 둘이며, 10짜리 둘과 5짜리 하나를 동시에 가질 수 없다. 이를 합치면 25보다 작은 동전들의 총액은 최대 24다.

따라서 최소 해의 25짜리 개수는 탐욕 방식의 $\lfloor n/25\rfloor$와 같아야 한다. 더 적으면 작은 동전으로 25 이상을 채워야 해서 앞의 성질과 모순이다. 나머지에서도 5·1짜리로 만들 수 있는 최적 해의 총액은 9 이하이고 1짜리는 4 이하이므로, 10·5·1짜리 개수도 차례로 탐욕 선택과 같아진다.

액면 5가 빠지면 논증은 성립하지 않는다. $25,10,1$로 30을 만들 때 탐욕 방식은 25와 1 다섯 개, 총 6개지만 10 세 개면 된다. 31도 탐욕은 7개, $10+10+10+1$은 4개다.

### 겹치지 않는 일정의 최대 개수

한 장소에서 시간 구간이 겹치지 않는 일정을 최대한 많이 선택한다. 끝나는 시각과 다음 시작 시각이 같은 것은 허용한다. 이 문제에서는 **종료 시각이 가장 이른 일정부터** 선택한다.

```text
schedule(talks):
    sort talks by finish time
    selected := empty list
    last_finish := -infinity
    for talk in talks:
        if talk.start >= last_finish:
            append talk to selected
            last_finish := talk.finish
    return selected
```

최적 해의 첫 일정 $o$보다 탐욕이 고른 첫 일정 $g$가 늦게 끝나지는 않는다. 따라서 최적 해에서 $o$를 $g$로 바꾸어도 뒤의 일정들과 겹치지 않고 개수도 같다. 첫 선택을 탐욕 선택과 맞춘 뒤 남은 일정에 같은 논증을 반복하면 최적성이 따라온다.

가장 일찍 시작하는 기준은 $[8,12],[9,10],[10,11]$에서 실패한다. 처음 구간을 고르면 하나뿐이지만 나머지 둘을 고를 수 있다. 가장 짧은 기준도 $[8{:}00,9{:}15]$, $[9{:}00,10{:}00]$, $[9{:}45,11{:}00]$에서 가운데 하나만 고르게 된다. 첫째와 셋째를 고르면 두 개다.

## 6. 정지 문제

임의의 프로그램 $P$와 입력 $I$에 대해 실행이 언젠가 멈추는지 항상 정확하게 판정하고 종료하는 알고리즘 $H(P,I)$가 있다고 가정하자. 다음 프로그램을 만든다.

```text
K(P):
    if H(P, P) says "halts":
        loop forever
    else:
        halt
```

프로그램을 문자열로 표현할 수 있으므로 자기 자신을 입력으로 줄 수 있다. 이제 $K(K)$를 생각한다. $H(K,K)$가 멈춘다고 판정하면 정의에 의해 무한 반복하고, 멈추지 않는다고 판정하면 즉시 멈춘다. 어느 경우든 판정과 모순이다.

따라서 모든 프로그램과 입력을 처리하는 그런 판정기는 존재하지 않는다. 특정 프로그램의 종료를 분석할 수 없다는 뜻이 아니라, **모든 경우에 성공하는 일반 알고리즘이 없다**는 뜻이다. 이는 단지 시간이 오래 걸린다는 복잡도 문제와 다르다.

## 7. 빅오의 정의와 증인

실행 시간을 기계에 종속된 초 단위로만 비교하는 대신, 입력 크기 $n$에 따른 기본 연산 횟수를 비교한다. $100n^2+17n+4$와 $n^3$은 작은 $n$에서 전자가 더 크지만, 충분히 큰 $n$에서는 후자가 더 커진다.

$$
f(n)=O(g(n))
\iff
\exists C>0\ \exists n_0\ \forall n>n_0,
\quad |f(n)|\le C|g(n)|.
$$

$C,n_0$를 증인이라고 한다. 둘은 $n$과 무관한 상수여야 한다. 빅오는 상수배를 허용한 점근적 상한이다. 항상 엄격히 느리게 자란다는 뜻은 아니며 같은 차수여도 포함된다. 엄밀히 $O(g)$는 함수들의 집합이므로 $f\in O(g)$가 정확한 표기이고, 등호는 관례다.

### 증인 찾기

$n>1$이면 $n\le n^2$, $1\le n^2$이므로

$$
n^2+2n+1\le4n^2.
$$

따라서 $C=4,n_0=1$이 증인이다. $n>2$에서 $2n\le n^2$을 사용하면 $C=3,n_0=2$도 가능하다. 증인은 유일하지 않다.

| 주장 | 가능한 증인 | 부등식의 근거 |
|---|---|---|
| $5n^3=O(n^4)$ | $C=5,n_0=1$ | $n^3\le n^4$ |
| $3n^2+5n+2=O(n^2)$ | $C=10,n_0=1$ | 각 항을 $n^2$의 배수로 제한 |
| $7n^2=O(n^3)$ | $C=1,n_0=7$ | $7<n$ |
| $7n^4-3n^2+6=O(n^4)$ | $C=16,n_0=1$ | 절댓값과 삼각부등식 |

더 큰 함수로 상한을 잡을 수도 있어서 $n^2=O(n^3)$은 참이다. 하지만 정확한 증가 차수를 말할 때는 가능한 한 밀접한 상한을 쓰는 것이 유용하다.

### 빅오가 아님을 증명하기

$n^2=O(n)$이라고 가정하면 충분히 큰 모든 $n$에서 $n^2\le Cn$, 즉 $n\le C$여야 한다. $n>\max(n_0,C)$를 선택하면 모순이다. 마찬가지로 $n^3\le C\cdot7n^2$는 $n\le7C$를 요구하므로 $n^3$은 $O(7n^2)$가 아니다.

몇 개의 수치만으로 불성립을 증명할 수는 없다. $2^n$이 $O(n^2)$가 아님은 비율로 보일 수 있다. $r_n=2^n/n^2$이면

$$
\frac{r_{n+1}}{r_n}=2\left(\frac n{n+1}\right)^2\ge\frac{32}{25}>1\quad(n\ge4).
$$

따라서 $r_n$은 일정 비율 이상으로 계속 증가해 어떤 상수보다도 커진다.

## 8. 함수의 증가와 결합

다항식 $f(x)=a_dx^d+\cdots+a_0$에서 $x>1$이면

$$
|f(x)|\le\sum_{i=0}^{d}|a_i|x^i
\le\left(\sum_{i=0}^{d}|a_i|\right)x^d.
$$

따라서 $O(x^d)$다. 최고차항의 계수가 0이 아니면 $f(x)/x^d\to a_d\ne0$이므로 하한도 같은 차수로 얻는다.

다음과 같은 간단한 제한도 유용하다.

$$
\sum_{k=1}^{n}k\le n^2,\quad
\sum_{k=1}^{n}k^2\le n^3,\quad
n!\le n^n,\quad
\log(n!)\le n\log n.
$$

로그는 밑이 1보다 큰 고정 상수라고 가정한다. 밑 변환 공식 $\log_bn=\log_an/\log_ab$에 따라 밑이 달라도 상수배 차이이므로 같은 점근적 차수다.

증가 차수는 대체로 다음 순서다. 이것은 모든 작은 $n$에서의 값의 대소관계가 아니라 충분히 큰 $n$에서의 증가율 비교다.

$$
1\prec\log n\prec n\prec n\log n\prec n^2\prec2^n\prec n!.
$$

고정된 양수 $c,d$와 $b>1$에 대해 $(\log n)^c$는 $n^d$보다, $n^d$는 $b^n$보다 느리게 증가한다. $1<b<c$이면 $b^n$은 $c^n$보다 느리고, 고정된 $c^n$은 계승보다 느리다.

예를 들어 증가 순서는

$$
(\log n)^2\prec8\sqrt n\prec2n\log n\prec n^2\prec1.1^n\prec n!
$$

이다. 조금 더 복잡한 목록도 차수를 묶어서 정리할 수 있다.

1. 상수 $10000$
2. $\log\log n$
3. $(\log n)^2$
4. $n^2(\log n)^3$
5. $8n^3+17n^2+111$과 $n^3+n(\log n)^2$: 둘 다 $\Theta(n^3)$
6. $1.5^n$
7. $2^n$
8. $2^n(n^2+1)$
9. $n!$

### 합과 곱의 빅오

$f_1=O(g_1)$, $f_2=O(g_2)$이면

$$
f_1+f_2=O(\max(|g_1|,|g_2|)),\qquad
f_1f_2=O(g_1g_2).
$$

공통 시작점 이후에 $|f_i|\le C_i|g_i|$를 적용한다. 합에는 삼각부등식과 $C_1+C_2$, 곱에는 $C_1C_2$를 사용하면 된다. 합에서 상쇄가 생길 수 있으므로 이 규칙은 우선 상한에 대한 규칙이다.

$$
3n\log(n!)+(n^2+3)\log n=O(n^2\log n)
$$

인 것은 각 항이 그 차수로 제한되기 때문이다. 또

$$
(x+1)\log(x^2+1)+3x^2=O(x^2)
$$

이다. 앞부분은 $O(x\log x)$이고, 뒷부분은 $O(x^2)$다. $3x+5x^2$는 $O(x^2)$, $(3x)(5x^2)$는 $O(x^3)$이며, $2x^3+3x^2\log x+100$은 $O(x^3)$이다.

## 9. 오메가와 세타

$$
f(n)=\Omega(g(n))
\iff\exists c>0\ \exists n_0\ \forall n>n_0,
\quad|f(n)|\ge c|g(n)|.
$$

오메가는 하한이다. 세타는 상한과 하한이 동시에 성립하는 경우다.

$$
f(n)=\Theta(g(n))
\iff
\exists c_1,c_2>0\ \exists n_0\ \forall n>n_0,
\quad c_1|g(n)|\le|f(n)|\le c_2|g(n)|.
$$

$n>1$에서 $4n^2\le4n^2+3n\le7n^2$이므로 $4n^2+3n=\Theta(n^2)$다. $8x^3+5x^2+7\ge8x^3$이므로 $\Omega(x^3)$이고, 다항식 상한까지 합치면 $\Theta(x^3)$다.

$$
\frac{n^2}{2}\le\frac{n(n+1)}2\le n^2\quad(n\ge1)
$$

이므로 $1+\cdots+n=\Theta(n^2)$다. $3x^2+8x\log x$도 $\Theta(x^2)$다. $x>1$에서 $x^3+2x+1\le4x^3$이므로 $x^3=\Omega(x^3+2x+1)$도 성립한다.

최고차항이 0이 아닌 다항식은 절댓값을 사용하는 정의에서 최고차항의 차수와 같은 세타다. 따라서 $3x^8+10x^7+221x^2+1444$는 $\Theta(x^8)$, $x^{19}-18x^4-10112$는 $\Theta(x^{19})$, $-x^{99}+40001x^{98}+100003x$는 $\Theta(x^{99})$다.

**빅오가 최악, 오메가가 최선이라는 뜻은 아니다.** 먼저 최악·평균·최선 중 어떤 실행 비용 함수를 분석할지 정하고, 그 함수의 상한·하한·차수를 각각 $O,\Omega,\Theta$로 표현한다.

## 10. 행렬 계산과 연산 횟수

시간 복잡도는 연산 횟수, 공간 복잡도는 사용하는 메모리의 양이다. 최악 경우는 크기가 같은 유효 입력 중 연산이 가장 많은 경우이고, 최선 경우는 가장 적은 경우다. 평균 경우는 입력의 확률분포에 따른 연산 횟수의 기댓값이다. 아래의 행렬 계산에서는 성분 하나의 덧셈과 곱셈을 상수 비용으로 가정한다. 정수의 비트 길이가 커지는 경우에는 그 산술 연산의 비용도 별도로 고려해야 한다.

```text
matrix_product(A[m,k], B[k,n]):
    for i := 1 to m:
        for j := 1 to n:
            C[i,j] := 0
            for q := 1 to k:
                C[i,j] := C[i,j] + A[i,q] * B[q,j]
    return C
```

결과 성분이 $mn$개이고 각각 $k$번 곱하므로 곱셈은 $mkn$회다. 위 코드 그대로면 0에 첫 항을 더하는 것까지 성분당 $k$회 덧셈을 한다. 첫 곱을 초기값으로 놓는 구현에서는 성분당 $k-1$회로 줄어든다. 두 $n\times n$ 행렬을 정의대로 곱하는 알고리즘은 어느 방식이든 $\Theta(n^3)$이다.

불 곱은 갱신을 `C[i,j] := C[i,j] OR (A[i,q] AND B[q,j])`로 바꾼다. 단락 최적화 없이 모두 계산하면 정사각행렬에서 AND $n^3$회, OR $n^3$회, 총 $2n^3$회다. 일반 행렬곱에는 스트라센 알고리즘처럼 $O(n^{\log_2 7})$에 계산하는 방법도 있으므로, 정의대로 계산한 알고리즘의 비용을 모든 알고리즘의 하한으로 해석하면 안 된다.

### 행렬 연쇄 곱셈

행렬곱의 결합법칙은 괄호를 바꾸어도 결과가 같다는 뜻이다. 행렬 자체의 순서를 바꾸어도 된다는 뜻은 아니다. 괄호에 따라 중간 행렬의 크기와 연산량은 달라진다.

$A_1$: 30×20, $A_2$: 20×40, $A_3$: 40×10이면

$$
\begin{aligned}
A_1(A_2A_3)&:\quad20\cdot40\cdot10+30\cdot20\cdot10=14000,\\
(A_1A_2)A_3&:\quad30\cdot20\cdot40+30\cdot40\cdot10=36000.
\end{aligned}
$$

10×100, 100×5, 5×50인 경우에는 반대쪽 괄호가 유리하다.

$$
\begin{aligned}
(A_1A_2)A_3&:\quad10\cdot100\cdot5+10\cdot5\cdot50=7500,\\
A_1(A_2A_3)&:\quad100\cdot5\cdot50+10\cdot100\cdot50=75000.
\end{aligned}
$$

## 11. 브루트포스와 문제의 복잡도

브루트포스는 정의에 따라 후보를 직접 검사하는 접근이다. 모든 점 쌍 중 가장 가까운 쌍을 찾는다면

```text
closest_pair(points[1..n]):
    best := infinity
    for i := 2 to n:
        for j := 1 to i - 1:
            d := (x[i] - x[j])^2 + (y[i] - y[j])^2
            if d < best:
                best := d
                answer := (i, j)
    return answer
```

로 계산한다($n\ge2$). 거리는 음수가 아니고 제곱근은 증가함수이므로 거리의 제곱만 비교해도 된다. 검사하는 쌍은 $n(n-1)/2$개여서 $\Theta(n^2)$다. 점이 1,000개이면 499,500쌍이다.

알고리즘 설계에는 탐욕과 브루트포스 외에도 문제를 나누는 분할정복, 겹치는 부분문제의 결과를 저장하는 동적 계획법, 불가능한 후보를 일찍 버리는 백트래킹, 무작위 선택을 사용하는 확률적 방법 등이 있다.

| 차수 | 이름 | 예시 |
|---|---|---|
| $\Theta(1)$ | 상수 | 입력 크기와 무관한 고정 개수의 원소 검사 |
| $\Theta(\log n)$ | 로그 | 정렬된 배열의 이진 검색, 최악 경우 |
| $\Theta(n)$ | 선형 | 최댓값 찾기, 순차 검색의 최악 경우 |
| $\Theta(n\log n)$ | 선형로그 | 병합 정렬의 비교·병합 작업 |
| $\Theta(n^2)$ | 이차 | 기본 버블 정렬, 모든 점 쌍 검사 |
| $\Theta(n^3)$ | 삼차 | 정의에 따른 정사각행렬 곱셈 |
| $2^n$개 후보 | 지수적 탐색 공간 | $n$개 명제변수의 모든 진리값 할당 |
| $n!$개 후보 | 계승적 탐색 공간 | $n$개 대상의 모든 순열 |

후보 개수와 전체 시간은 다를 수 있다. 예를 들어 SAT의 모든 할당이 $2^n$개여도 각 할당에서 식을 검사하는 비용이 추가된다.

### P, NP, NP-완전의 구별

결정 문제는 답이 예 또는 아니오인 문제다. **P**는 입력의 표현 길이에 대해 결정적 다항 시간에 풀 수 있는 결정 문제들의 클래스다. **NP**는 답이 예인 입력에 대해 다항 길이의 증명서가 존재하고, 그 증명서를 다항 시간에 검증할 수 있는 결정 문제들의 클래스다. NP는 “다항 시간에 풀 수 없는 문제”의 약자가 아니다. $P\subseteq NP$다.

**NP-완전**은 NP에 속하면서, NP의 모든 문제가 다항 시간 환원으로 그 문제에 옮겨지는 경우다. 따라서 NP-완전 문제 하나에 다항 시간 알고리즘이 있으면 $P=NP$가 된다. SAT는 대표적인 NP-완전 문제다. 진리값 할당을 받으면 식이 참인지 빠르게 확인할 수 있다는 점과, 만족하는 할당을 찾아야 한다는 점을 구별한다.

단순한 완전 탐색이 지수 시간이라는 사실만으로 문제 자체가 다항 시간에 풀리지 않는다고 증명한 것은 아니다. 또한 다항 시간이라는 이론적 분류가 실용적으로 빠르다는 보장은 아니다. $n^{100}$도 다항식이고, 큰 상수와 메모리 비용이 실행을 어렵게 만들 수 있다. 반대로 어려운 최적화 문제에서도 특정 입력의 구조, 근사 알고리즘, 휴리스틱이 유용할 수 있다.

### 증가율을 시간으로 바꾸어 보기

기본 연산 하나가 가정상 $10^{-11}$초이고 정확히 $f(n)$번 실행된다고 놓자. $n=10^6$에서 $n$번이면 $10^{-5}$초, $n^2$번이면 10초다. $n=100$에서 $2^n$번이면 약 $4.0\times10^{11}$년이다. 이 숫자는 실제 장비의 측정값이 아니라 증가율의 차이를 보기 위한 계산이다. $\Theta$ 표기만으로는 상수와 실제 연산 비용을 알 수 없으므로 그대로 실행 시간을 예측할 수 없다.
